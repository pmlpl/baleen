# 缺陷台账汇总（defects_ledger）

> 数据：`eval/analysis/defects_ledger.csv`（76 条，2026-10-28 ~ 2026-11-18；前 75 条从 18 篇日志 + STATUS 闭环区提取，n02 为负例评测 live 档抓到后按维护约定追加）。
> 本文件是台账的**分析层**：失败模式归类、A 档转化缺口、未闭环清单。改动台账后同步本文件统计。

## 定位

缺陷台账不是档案柜（日志和 git 历史已经记录了每个缺陷的来龙去脉），它的价值在两件向前看的事：

1. **模式归类**——把孤立的已修复缺陷聚成失败模式，回答「下一轮评测建在哪、prompt 往哪调」；
2. **A 档转化**——把「已修复但没钉住」的缺陷变成回归评测用例，防止老 bug 随代码改动 / prompt 调优 / 模型更换复活。

## 字段与分档

CSV 字段：`date, found_via, module, symptom, root_cause, fix, verification, tier, conversion`

| 档 | 定义 | 处理 |
|---|---|---|
| **A** | 行为类缺陷：代码被改 / prompt 被调 / 模型或语料变化可能复发 | 值得钉回归评测；`conversion` 列记录钉没钉住 |
| **B** | 环境怪癖 / 外部平台行为：模型特性、代理、风控、进程管理 | 记档即可，建评测无意义 |
| **C** | 一次性问题：已修死，正常开发流程测试覆盖，无复发面 | 什么都不做 |

## 统计（2026-11-17 快照）

- **总数 76** = A 30 / B 10 / C 36
- 按发现途径：**使用 44（58%）** / 开发 22 / 评测 9 / 评审 1 —— 真实使用是最主要的缺陷来源，印证「candidates 归档 + 人工复核」是正确的评测数据闭环
- 按模块：视频 17 / 问答 18 / 前端 17 / 导入 11 / 文档 5 / 环境 2 / 检索 3 / 评测 3
- **视频流水线 5 天（11-12 上线）就贡献 17 条**，且 11 条集中在 organizer 对视频转写输入的行为——是当前最脆的一环

## 五个失败模式（A 档归类）

### 模式① organizer / AI 整理行为失控（面对视频转写与清单型内容）

| 缺陷 | 日期 | 根因 |
|---|---|---|
| 《博弈论》评级 normal 失真 | 11-14 | prompt 模糊标准 + 模型锚定「来源是视频」 |
| 网关笔记全扁平（多章指引不生效） | 11-14 | prompt 内「一个主题一节」与多章规则冲突 |
| 4986 正文截断 94% | 11-16 | 预算硬编码 6000/8192 |
| 22min 视频 H1 17 个 / 图片扎堆 | 11-16 | 清单型内容过度触发多章规则；场景检测不看信息密度 |
| 课程推广视频被 G2 拒收 | 11-12 | 「判官」语义不适用视频 |

**结论**：5 条全部指向「organizer 面对视频转写这种口语、清单型输入的行为」。直接支持「G2 评测样本按来源分层（文档 / 视频转写 / 问答导出）」——当前 ok 口径样本以文档为主，对这类失败模式无区分度。

### 模式② 静默截断 / 静默丢失

切块碎片化（10-28，测试全绿真实数据 11.6%）→ 代码块超 480 静默截断（10-29）→ 列表内图静默丢失×2（11-03）→ max_tokens 3000 静默半篇（11-05）→ 4986 截断 94%（11-16）。

**纪律**（已逐步建立，需评测钉住）：凡截断必显式留痕——`finish_reason` 读取、续写、`failed_pages` 留痕、末尾 ⚠️ 警告、`low` 帧不落盘。

### 模式③ 渲染层与数据层脱节

mermaid 裁切根因#1#2（10-30/31）→ 表格拍平 + mermaid 吞正文（11-05）→ 出处死文本（11-05）→ QA 公式一片红（11-15）。

**共性**：生成/存储是对的，前端解释错了。回归手段目前全是**一次性截图对照和临时探针**（非 pytest）——渲染回归是评测面的空白区。

### 模式④ 字面启发式做语义判断

「数据库」命中发票 OCR → LLM 拒答（10-30，催生 [NO_KB]）→ 挂图搜「图片转文字/OCR 工具」（11-05）→ 中英连写分词（11-05）→ ReAct 碎片匹配（10-30）。

**共性**：`_has_relevant_hit` 这类字面启发式被当成语义闸，误触发联网兜底。评测面缺失：query 集没有负例（库里没有的问题 / 不相关的问题），测不出误触发。

### 模式⑤ 管线接缝的元数据正确性

扫描件标题变「第 1 页」（11-02）→ 4986 标题 474 字 blob（11-16）→ 视频标题换行 OSError 22（11-16）→ 失败导入误报「已导入过」（11-14）→ 前缀不对齐命中率永远「—」（10-30）。

**共性**：各环节交接处（organizer↔notes.title、md 标记↔文件名、dedupe 语义、存储↔LLM 重放）的一致性无自动校验。

## 维护约定

1. **新增缺陷**：修完后往 CSV 追加一行（日期 / 发现途径 / 模块 / 现象 / 根因 / 修复 commit / 验证 / 分档），当天日志里已写的不用展开，CSV 一行即可。
2. **转化**：A 档缺陷被评测/测试钉住时更新 `conversion` 列；backlog 清单相应划账。
3. **复盘**：每月抽 10 条 A 档重审一次分档（语料/架构变化可能让 B 档变 A 档，如换模型）。
