# heading 前缀 A/B 实验（ADR 0004 §5）

- **执行者**：ZCode（主人批准，线 N-追加）
- **日期**：2026-10-29
- **脚本**：`eval/scripts/prefix_ablation.py`（纯内存，只读库，**不碰 `chunk/`**）
- **要回答的问题**：ADR 0004 §5 写「把 `heading_path` 拼进 embed 文本能**显著提升判别力**」——这是一句**无证据断言**（ADR 没做实验、没给数据）。`eval/ablation.md` §9.1 又发现这个前缀**只落地了 code 块**（text/table 占 39% 没加）。到底该不该补到 text/table？**先做同口径 A/B 再决定改不改生产**（`HANDOFF.md` §1 真问题 6 的要求）。

---

## 1. 结论先行

> **不给 text/table 补前缀。ADR §5 的「显著提升判别力」断言不成立。**

三条都站得住：

1. **Recall@5 反而掉 2 条**：V1（生产）100% → V2（给 text/table 补前缀）88.9%，**−11.1pt**。被挤出去的是 q06（名次 3→7）和 q15（4→8）。
2. **MRR 升是假象**：V2 MRR 0.730 > V1 0.653，但那是因为**已经命中的 query 排得更前**（q04/q10/q16 都跳到第 1 名），不是「多找到了」。MRR 不截断、被挤到第 7/8 名的 query 仍贡献 1/7、1/8，掩盖了召回损失。
3. **V3（全量统一，连 code 前缀也换成 canonical）不比 V2 好**：R@5 同样 88.9%，MRR 0.660 还更低。→ **code 现有的 `# {hp} ({lang})` 前缀别动。**

**这正是「先 A/B 再改生产」的价值**：若照 ADR 那句断言直接给 text/table 加前缀，会净损失 2 条召回。本实验拦住了这个错误改动。

## 2. 实验设计（与 chunk 尺度消融同口径）

### 2.1 固定什么

| 项 | 值 |
|---|---|
| 切块档位 | **300 档**（= 生产值，今早复核后 R@5=100% 的档；前缀问题与切块尺度正交，固定一档） |
| query 集 | 20 条（已人工复核，`eval/queries/queries.csv`） |
| 语料 | 11 篇 / 184 父块 / 309 个可向量化子块 |
| embedding | 本地 `bge-large-zh-v1.5`（1024 维，`cuda`，输出已 L2 归一化） |
| query 侧 | `embed_query()`（带非对称前缀） |
| passage 侧 | `embed_passage()`（不加前缀） |
| 检索 | 纯向量路：点积 = 余弦 |
| 命中口径 | 父块级、`heading_path` 对得上（`ablation.md` §3） |

子块 `block_type` 分布（300 档、309 个）：`text` 103 / `code` 178 / `table` 28。

### 2.2 变什么：三变体（只动喂给 embedding 的 `.text`）

| 变体 | code 块 | text/table 块 |
|---|---|---|
| **V1 = 生产现状**（基线） | `# {heading_path} ({lang})\n{正文}` | 纯正文（无前缀） |
| **V2 = 给 text/table 补 §5 前缀**（主比较） | 不动（= 生产） | `{笔记标题} > {heading_path}\n{正文}` |
| **V3 = 全量统一 §5** | `{笔记标题} > {heading_path}\n{正文}`（旧前缀替换） | `{笔记标题} > {heading_path}\n{正文}` |

### 2.3 注入方式（关键：不碰 chunker）

前缀注入在**评测侧后处理**：`prefix_ablation.py` 调 `ablation.build_corpus` 切一次块（300 档），缓存每子块的原始 `.text` + `block_type` + 所属父块的 `note_title`/`heading_path`，然后按变体**原地改写 `child.text` → 重新 `embed_passage` → `evaluate`**。`chunker.py` / `pipeline.py` / 生产 embedding **一行未动**。

> 唯一对 `ablation.py` 的改动是给 `ChildEntry` 加了一个 `block_type` 字段（向后兼容，既有 chunk 尺度消融不读它、数字不变）。

### 2.4 回归断言

V1 = identity 变换（不改任何 `.text`），**必须复现生产 300 档数字**。实测：V1 R@5 = 100.0%、MRR = 0.653 ——与 `ablation.md` §11 宽松版 300 档**逐位一致** ✓。脚本结尾还断言 chunker 常量已还原成 300/250/400 ✓。

## 3. 主表：三变体 × 指标

**n = 18 正例；命中口径见 `ablation.md` §3 / §11。**

| 变体 | Recall@5 | Recall@10 | MRR | ΔR@5 vs V1 |
|---|---|---|---|---|
| **V1（生产）** | **100.0%** (18/18) | 100.0% | 0.653 | — |
| V2（text/table 补前缀） | 88.9% (16/18) | 100.0% | 0.730 | **−11.1pt** |
| V3（全量统一 §5） | 88.9% (16/18) | 100.0% | 0.660 | **−11.1pt** |

- V2 与 V3 的 R@5 完全相同（都掉 q06、q15 两条）；MRR 上 V2 > V3，说明**把 code 的旧前缀换成 canonical 没好处、反而拉低 MRR**。
- 按 §1 预注册判据（「V2 在 R@5 或 MRR 上净增 ≥1 条**且无回归**才算弱正向」）：R@5 回归 2 条 → **不成立**，落到「不改生产」一支。

### 4.1 两个方向同时发生

- **掉出 top-5（造成 R@5 −2）**：`q06`（3→7）、《闭包》成因的改写问；`q15`（4→8），Agent 学习路径的长查询。两条都是**不含笔记标题/heading 词**的 query。
- **跳到第 1 名（造成 MRR 升）**：`q04`（2→1）、`q10`（3→1）、`q16`（3→1）。
  - 其中 `q10` 特别值得记：在 chunk 尺度消融里它是**唯一 R@5 未命中**的 query（200/400 档第 9/11 名），加前缀后变**第 1 名**。前缀对「主题明确、能对上某节标题」的 query 确实锐利。

---

## 5. 怎么读这个结果（R@5 掉、MRR 升不是矛盾）

- **MRR 不截断**：被挤到第 7/8 名的 q06/q15 仍贡献 1/7、1/8，而跳到第 1 的 q04/q10/q16 贡献从 1/2、1/3 涨到 1。后者的增量更大，所以 MRR 净升。但 **R@5 看的是「能不能进前 5」**，q06/q15 一掉就是 2 条 = 11.1pt。
- **为什么 q06/q15 反而变差**：这俩 query 是改写/长查询，**不含笔记标题、也不含 heading 原文**。给 passage 加 `{标题} > {heading}` 前缀后，passage 向量被标题/面包屑拉偏，与「不含标题的 query」相似度反而下降。这是**非对称检索**下的典型副作用——passage 侧加了主题锚，query 侧没加对应信号。
- **净判断**：baleen 的核心价值是「**带出处的检索**=能找到」，**Recall 比 MRR 更重要**。前缀是「**用 2 条召回换排序锐度**」，不划算 → **不改生产**。

## 7. 与 `ablation.md` §9.1 / HANDOFF §1 真问题 6 的关系

- §9.1 指出 ADR §5 前缀**只落地了 code**（text/table 占 39% 没加），并说「正确顺序是先做同口径 A/B 再改生产」。
- **本 A/B 就是那条 A/B**，结论：**不要裸加**。ADR §5「显著提升判别力」断言**不被支持**——前缀对部分 query（主题明确的）有用，对另一部分（改写/长查询）有害，净效应是 Recall 下降。
- **若以后想再推进**（不在本次范围）：试「query 侧也加同构前缀」对冲非对称副作用、或「只给 table 加、text 不加」的细分变体、或在混合检索（trgm+RRF）下复测——词法路可能救回 q06/q15。但这些都是新实验，结论出来前不动生产。

---

## 8. 局限（诚实写）

1. **n=18，2 条 = 11.1pt**，仍是小样本；但方向（R@5 不升反降）清楚到足以否决「裸加前缀」。
2. **只测纯向量路**。生产是 trgm + 向量 + RRF，词法路对 q06/q15 这类不含专有名词的改写 query 可能有帮助——本实验为了隔离「前缀」这一个变量，故意关掉了词法路。
3. **语料 11 篇**，其中 3 篇是合成冒烟假数据（当干扰项，未出题）。
4. **只动 `.text` 前缀**，没动切块尺度、没动 `HARD_TOKEN_LIMIT`；加前缀会增加 passage 长度，但都远未触顶（前缀 ~20 字）。
5. V3 把 code 的 `({lang})` 信息丢掉了（换成 canonical），这可能解释 V3 MRR 略低于 V2——但 V3 本就不是推荐项，细究无意义。
