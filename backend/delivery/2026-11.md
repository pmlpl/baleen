## 2026-11-01 · 图片视觉理解(ADR 0006) · 执行者：ZCode

提交 `b712624` · api.md v13 · 基线 274

### 产物
- `backend/app/service/parse/vision.py`（新）：图片→data URL→视觉模型转写 Markdown→`parse_md_text`→blocks
- `backend/app/service/parse/router.py`：`parse_file(path, client=)` 可选注入视觉 client
- `backend/app/api/qa.py` + `service/qa/answerer.py`：`_load_hit_images` / `attach_images`，问答命中笔记时原图回传（≤2 张）
- `docs/adr/0006-image-vision.md`（新）+ `docs/api.md` v13；测试 `test_vision.py` / `test_qa_image.py`（+11）

### 为什么做
图片笔记是空壳——导入的图没文字、问答看不到图。给 G0 装眼睛：导入时视觉模型把图「看」成 Markdown 正文走完整流水线（降级 `no_text_expected`，绝不拖垮导入），问答命中时原图给模型「看着答」。识别引擎=用户自配 LLM，零新依赖。

### 自测
274 passed（+11）。e2e 全链路（注册→设 key→Pillow 造图→上传→arq→G1/G2→问答）：G0 ok / G1 accept / G2 accept，笔记 markdown=转写正文；问答 `images_attached=1`，答案给出图中校验编号 ZEBRA-7742 并描述其在图中的布局位置——模型真在看图。

### 已知限制
- 推理型网关模型（glm-5.2）干不了视觉转写：`max_tokens=8` 探测返回 6 字符空转写被 G1「极短」拒。需非推理模型（deepseek-flash），已记 ADR 0006，不做代码兜底（与整理线同口径）。
- 含图笔记的内容编辑仍禁（md 往返丢 doc 里 image 块）——11-02 已放开。
- 扫描件 PDF 未覆盖——11-02 补。

- `docs/adr/0009-async-video-extraction.md`（新建）

### 为什么做
v22 的 whisper 模式在 API 请求内同步阻塞 2-3 分钟，长视频（>30 分钟）直接 502 超时。用户要导入 1 小时视频（如"AI Infra 一小时入门"）。改为 worker 后台异步后：API 立即返回，worker 有 2 小时超时，支持 ≤60 分钟视频，前端显示多阶段进度。

### 自测
434 passed（+11：worker 5 + sources_url 6，基线 423→434 零回归）；vue-tsc --noEmit 过。doc_lint ERROR 0。

### 设计要点
- **占位 sha 策略**：source.sha256 = `"video:{bvid}:whisper"`（不更新为真实 sha），job.dedupe_key 匹配，`get_source_status` 查找逻辑不变。dedupe 基于 BVID。
- **pipeline `source_id` 参数**：视频路径跳过 source/job 创建，用预创建的，G0→embed 代码完全共享。
- **worker 不 claim job**：留给 pipeline 的 `jobs.claim()` 做（queued→running），worker 崩溃可 arq 自动重试。
- **进度传达**：worker 通过独立 DB session 更新 `source.parse_meta["video_stage"]`，前端轮询读取。

### 已知限制
- source.sha256 是占位值（非真实内容 sha），内容寻址 dedupe 不适用于视频（BVID dedupe 覆盖常见场景）
- `max_jobs=1`：视频提取和文件导入串行（视频提取时文件导入排队）
- subtitle 模式保持同步（秒级，不需要异步）
