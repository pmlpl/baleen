# ADR 0005：导入后主动总结（阶段3）与会话产出笔记（阶段4）

- 状态：**提案（待主人拍板，未实施）**
- 日期：2026-10-30
- 提出者：ZCode（主人指令「按路线图完成剩下内容」触发设计）
- 关联：ADR 0001（导入状态机）、AGENTS.md §8「明确不做」、HANDOFF 路线图

---

## 1. 背景

主人的完整版愿景：打开会话 → 选择项目文件夹 → 导入笔记 → 过三闸 → **总结并解析、开始和用户交流** → **产出会话笔记或其他产物**。

前四步已全部落地（导入链闭环 + 聊天式多轮问答 + 流式）。本 ADR 设计最后两步：

- **阶段3（主动总结）**：导入完成后，系统主动生成该笔记的要点摘要，并开启一个可以继续聊的会话
- **阶段4（产出会话笔记）**：把一场问答会话整理成一篇结构化笔记，落成文件产物

## 2. §8 边界分析（为什么这不违反「明确不做」）

AGENTS §8 排除的是「**让 agent 自主决定导入流程的下一步**」。本提案的两步都是**固定流水线步骤**：

- 阶段3：导入完成 → 生成摘要 → 建会话 —— 触发时机、行为全部确定，无自主决策
- 阶段4：用户**点击按钮**触发 → 用户驱动，非 agent 自主

结论：**不违反 §8**，但摘要失败必须静默跳过（不得让导入失败）、产出必须用户显式触发——这两条写进验收标准。

## 3. 阶段3 设计：导入后主动总结

**流程（worker 内，向量化落库之后追加一步）**：

```
import_file(...) 完成
  → LLM 生成摘要(200-400 字要点 + 3 个建议问题,基于 note 正文)
  → 自动创建一个 qa_sessions(title=「新导入:{文件名}」)
  → 写入首条 assistant 消息(content=摘要+建议问题)
  → 失败则静默跳过(导入本身不受影响)
```

- **存储零新增**：摘要就是该会话的首条 assistant 消息——复用现有 qa_sessions/qa_messages 全部设施，前端侧栏自动出现「新导入:xxx」，点开即聊
- **前端**：问答页侧栏出现新会话（现有轮询/刷新即可见），无需新页面
- **代价**：每次导入 +1 次 LLM 调用（摘要），导入耗时 +5-15s
- **降级**：LLM 失败/未配 key → 跳过（记录 meta），导入照常成功

## 4. 阶段4 设计：会话产出笔记

**流程（用户点击「存为笔记」触发）**：

```
问答页「存为笔记」按钮
  → LLM 把当前会话整理成一篇结构化 markdown 笔记(要点+代码+出处)
  → 落盘 {仓库根}/notes_out/{YYYY-MM-DD}-{标题}.md (gitignored)
  → (可选,拍板点) 同时收进笔记库
```

- 落盘目录 `notes_out/` 是「项目文件夹」愿景的最小落地；后续可升级为按会话选择目标文件夹
- 「收进笔记库」路径：直接建 note（跳过 G0/G1，因为来源可信）还是过三闸——**待拍板**

## 5. 待主人拍板的决策点

1. **阶段3 摘要放哪**：A. 自动建「导入会话」（推荐：复用全部设施、侧栏直接可见） B. 存 `notes.summary` 列（笔记详情页显示） C. 两者都做
2. **阶段4 产出的笔记要不要收进笔记库**：A. 只落文件 B. 落文件 + 直接入库（跳过闸门） C. 落文件 + 过三闸
3. **实施顺序**：阶段3 → 阶段4 串行，还是只先做一个

## 6. 代价与风险

- 每次导入 +1 次 LLM 调用；会话整理 +1 次（较长，~20-40s）
- 摘要/整理质量依赖模型；glm-5.2 推理模型可用
- 自动建会话会让侧栏随导入增长（可后续加归档/删除批量管理）

## 7. 不做的

- 不做 agent 自主多步规划（每次只做固定的一步）
- 不做定时/后台自动整理（一切用户显式触发）
- 不做实时协作、移动端（§8 既有边界不变）
