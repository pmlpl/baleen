# ADR 0010：问答链 agent 自主权边界（L1：answerer 决策树上翻 tool-call loop）

## 1. 背景：硬编码决策树的天花板

问答链在 2026-11-20 之前是一条**代码写死的决策树**（`app/api/qa.py`）：

```
改写检索词（LLM）→ 检索 top-k → _has_relevant_hit（字面关键词检查）
  ├─ 命中相关 → answer()（KB 版）→ 答 [n] 引用
  │     └─ LLM 输出 [NO_KB] → 联网搜索 → answer_web() / 自身知识二次答
  └─ 不相关 → 联网搜索 → answer_web()
```

它的根本缺陷是**缺陷台账失败模式④「字面启发式做语义判断」**的集中体现：

- **n02（Hadoop 生态圈组件）**：库里只有 Google 论文起源一段，`_has_relevant_hit` 判「沾边」就混合作答——11-18 靠给规则 2 加「部分相关判定」硬修（prompt 层），但「这段只讲了起源没回答组件清单，该换词再搜或转联网」这个判断本质上**只有 LLM 能做**，字面检查永远做不了；
- 「换个词再搜一次」这条路径**根本不存在**——检索只跑一次，脱靶就脱靶（只能靠改写器在提问侧缓解）；
- 「资料够不够答」由两个字面闸（命中数、关键词命中）代理，语义上既会误放（n02）也会误拦（发票税率 b01 靠 [NO_KB] 二段兜底救回）。

## 2. 决策：上翻为 agent loop（L1），自主权按边界表切分

把「检索→相关性判定→[NO_KB]→联网/自答」这棵树上翻为 **LLM 在 loop 里选工具**的 agent。设计基准（主人定稿，2026-11-20）一句话：

> **三明治结构**——入口契约在马具（system prompt），中间语义决策在脑（LLM 选工具），出口校验在马具（引用真实性、flag 完整性、预算回落）。

### 2.1 三道测试：决定权能不能交给脑，先过这三关

| 测试 | 问的是什么 | 本案的答案 |
|---|---|---|
| ① 错了赔得起吗 | 该决定的错误成本 | 赔得起：最坏情况回落到现有决策树（§2.4），单次问答最多多花几次 LLM 调用 |
| ② 事后验得了吗 | 可验证性 | 验得了：每步 trace 留痕（§4），负例集 8 条回归 + 每答调用次数/时延/缓存有数 |
| ③ 有没有利益冲突 | 决策者会不会「永远觉得自己还差一步」 | 预算和停不停**永远在代码**（§2.3 脑不执缰），脑没有「多跑一步」的收益 |

三道全过才交给脑。**过不了的（见 §2.2）留在代码。**

### 2.2 自主权边界表（L1 范围）

| 决定 | 谁做 | 护栏 |
|---|---|---|
| 换个词再搜 / 资料够不够 / 何时转联网 | **脑**（LLM 在 loop 里选 `search_kb` / `search_web` 工具） | MAX_STEPS；「挂图不搜网」进 system 宪法**且代码不给这个工具**；负例集回归 |
| 引用谁、引多少 | **脑** | **引用真实性校验在代码**：[n] 必须映射真实 note_id / [W n] 必须映射真实 url；假引用 = 拒收重写一轮，仍假 = 摘掉 |
| [NO_KB] 发不发 | **脑判断 + 代码执行** | 缺 flag / 假引用 = 拒收重写；**[NO_KB] 协议本身永在代码层**（出 flag 后的兜底分支不动） |
| 预算 / 停不停 | **代码**（脑不执缰——它永远觉得自己还差一步） | MAX_STEPS 硬上限 + 总时间预算 + 每步超时；**超了回落现有决策树，最坏情况 = 现状** |
| 删/改笔记、重新导入、模型/渠道选择 | **代码** | 本批不做（L3 库操作 agent 另立 ADR） |

### 2.3 脑不执缰

预算三道闸全在代码：`AGENT_MAX_STEPS`（LLM 调用轮数上限）、`AGENT_STEP_TIMEOUT`（每步超时）、`AGENT_TIME_BUDGET_S`（总时间预算，步间检查）。任何一个触顶 → `run_agent` 返回 `None` → 调用方回落现有决策树。脑**不知道**预算数字（prompt 里不写「你还有 N 步」），它只负责当前的语义判断。

### 2.4 灰度 → 默认开：开关 + 回落，最坏情况 = 现状

`app_settings.agent_enabled`：迁移 0016 引入时按任务书口径**默认关**；**主人 2026-11-20 验收时改拍「默认开」**（原话：「还要我手动去打开吗，我们都已经是 agent 模式了，那前端原来的旧对话模式就不要了呀」）——迁移 0017 翻转 server_default 并把存量行全部置 true。

翻转后的语义：**NULL/true = agent loop（默认）**；**false = 显式关回旧决策树**（紧急开关 / A-B 对照）。旧决策树代码保留但不再是默认模式——它只在两处出现：用户显式关掉时（kill switch），和 agent 预算耗尽/LLM 失败时的代码层回落（与本开关无关，永远在）。这满足 ADR 0001 的可复现/可排查/成本可控三条约束：一条 PUT 即可回到确定性世界。

## 3. 与 ADR 0001 决策 5 / AGENTS §8 的关系（不是推翻，是场景切分）

ADR 0001 决策 5「导入是确定性状态机，不是 agent loop」写着**「何时该推翻：永远不该。灵活性放在闸门的判定逻辑里，不放在流程控制里」**。本 ADR **不推翻它**：

- **导入流水线不动**：G0/G1/organizer/切块/向量化仍是确定性状态机，必须可重放、可断点续跑——那里错了要赔的是整篇笔记，三道测试①（赔得起吗）过不了；
- **场景差异**：问答是**交互式、单次请求粒度、可即时反馈修正**的——LLM 多试两次词的代价是几秒时延和几分钱 token，且用户就在对面能看见答案好坏；导入是**批式、无人值守、产出持久化**的——错了静默进库，没人看着；
- 同理 AGENTS §8「自研 agent 框架不做」针对的是**框架**（一套通用抽象）。本 ADR 的 agent loop 是 ~100 行**业务代码**（while 循环 + function calling + 预算 + 留痕），不引 LangChain/LangGraph/AutoGen 任何依赖，不是框架——引框架反而违背「可复现/可排查」（多一层别人代码的行为）。

## 4. 消息结构与留痕

- **消息结构 append-only**（与 digest Tier-1 同构：不可变前缀 + 尾部追加）。首轮 user 消息由现有 `build_qa_messages` 生成（字节与现状一致）→ 保前缀缓存；agent 规则作为**第二条 system**追加（`AGENT_ADDENDUM`，常量字节）；工具轮次在尾部追加 assistant(tool_calls) + tool(结果) 消息，不动前缀。**工具结果进窗口前先压缩**（KB 命中按 token 预算截断、Tavily 结果沿用 1200 字符口径 + 总量上限），防灌水。
- **留痕 = 授权审计**：照 video_log 模式，每步记 `{step, kind, tool, arg, result, latency_ms}`——工具调用（含 query 摘要）和 LLM 调用各一条，全量存 `qa_messages.trace`（JSONB，迁移 0016），经 `MessageOut.agent_trace` 透出（旧消息/老路径 = null）。授权审计的含义：**脑做了什么决定，事后必须能一条条对账**，否则 §2.1 测试②「验得了吗」不成立。

## 5. 工具与引用台账（出口校验的实现）

- 两个工具：`search_kb(query)`（现有混合 RRF 检索，owner 隔离、top_k 同请求参数）、`search_web(query)`（现有 Tavily）。**挂图时 `search_web` 不注册**——「挂图不搜网」是产品规则，宪法不能靠被治理者自觉。
- 引用台账：初始 `<context>` 命中是 [1..n]；`search_kb` 结果**接着编号**（[n+1…]），`search_web` 结果用 [W1…]。台账里每条都连着真实 note_id / url——出口校验（假编号拒收重写一轮，仍假摘掉）和 citations 构建都从台账走，**代码永远不造 note_id**。
- [NO_KB]：协议不动——出 flag 后仍走代码层的自身知识兜底（与现状同文案同语义）。

## 6. 已知限制与后续

- **流式（v34，主人验收反馈驱动）**：`run_agent_iter` 为单一异步生成器实现、两种消费——非流式（`run_agent`，含修复轮）与流式（`gen()`：最终答案边生成边放行、工具轮发 `status` 进度事件；[NO_KB] 首行门扣下标记）。**流式跳修复轮**（已放行文本无法收回）：幻觉编号只从 citations 剔除，正文死徽章与决策树流式同语义（单测钉住两种模式差异）。
- **首答时延**：agent 多轮 = 首 token 前多次 LLM 往返（流式路径下 v34 起最终答案逐段放行）；实测负例 8 条每答 2 次调用、P50 12.3s（与决策树档同量级，见 `eval/runs/agent_report_2026-11-20.md` §3）。
- **前缀缓存——悬念已结清（D 阶段实测）**：`tools` 参数**不打断** DeepSeek 前缀缓存；agent 模式逐轮 hit 照常累积（append-only 设计生效），多轮探针 agent 开 62.4% vs 关 56.7%（同 miss 形态 ≈ 每轮固定 ~1.8k 新 token）。教训一条进缺陷台账：**addendum 必须显式声明对旧规则的优先级**（首跑时基础契约规则 2 的 [NO_KB]+自身知识压过了工具指引——模型从不调 search_web，改判据前先修 prompt）。
- **负例判据精细化（2026-11-20，待主人复核）**：agent 的诚实归因形态（答案主体 [W n] + 开头明示「以下来自联网」+ 背景句库内真归因 [n]）是决策树时代不存在的第三种形态。判据改为 **FAIL = 库内引用 且 未联网**（真混合作答，抓瞎引能力不减）；已联网时背景真归因记 PASS 留档人工抽查。严格口径读数在报告中并行保留。主人若倾向「背景不挂徽章只文字提及」，改 `AGENT_ADDENDUM` 一条规则即可。
- L2（工具扩到库内写操作预演）/ L3（笔记编辑 agent）不在本批，届时另立 ADR 重新过三道测试。
- 负例回归口径：`negative_eval --live` 8/8 是本 ADR 的验收面之一；n02 的期望路径 = 换词再搜 → 判定仍答不了 → 转联网（或干净自答），**不许答案内容由库内引用背书**（真混合作答）。
